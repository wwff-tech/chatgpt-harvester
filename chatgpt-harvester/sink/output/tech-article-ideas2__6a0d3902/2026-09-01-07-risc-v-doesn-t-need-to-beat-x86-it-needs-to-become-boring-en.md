### 7. **“RISC-V Doesn't Need to Beat x86. It Needs to Become Boring Enough for CUDA.”** — Long-form / hardware


At Hot Chips 2026, NVIDIA laid out concrete requirements for RISC-V CPUs participating in CUDA and NVLink Fusion systems. Nvidia pointed to RVA23 profiles, ACPI/UEFI server standards, PCIe I/O coherency and peer-to-peer support, while naming SiFive as its RISC-V NVLink Fusion CPU partner. 

**Angle:** We've touched RISC-V servers recently, so don't make this “RISC-V is coming to servers” again.

The more interesting thing is **standardisation defeating configurability**.

RISC-V's great feature is:

> choose the extensions you need.

A binary software ecosystem's great requirement is:

> please stop choosing differently.

RVA23 and server-platform profiles are therefore doing something essential: deliberately constraining architectural freedom so software can assume a predictable baseline.

That's a recurring lifecycle for successful extensible platforms:

`experimentation`

→ `many combinations`

→ `ecosystem emerges`

→ `profiles`

→ `boring compatibility`.

The paradox:

> **RISC-V becomes more commercially useful as some of its freedom becomes less relevant to software developers.**

Nvidia caring about this is a stronger maturity signal than another SBC announcement because CUDA brings an enormous binary software ecosystem with it.
