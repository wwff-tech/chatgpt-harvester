### 7. Generated Code Is Moving From Build Artefact to Source Artefact


The AMD graphics contribution also exposes an interesting maintenance choice: huge register definitions derived from silicon specifications live in the kernel source tree rather than necessarily being regenerated by every kernel builder. 

**Angle:** Generated code has traditionally been treated as something to avoid committing:

`schema → generator → build artefact`.

But there are legitimate reasons to commit it:

`reproducible build without generator`

`stable reviewable diff`

`no dependency on proprietary source schema`

`toolchain independence`.

Hardware makes this particularly awkward because the **true source** may be an internal vendor database the open-source project cannot redistribute.

So the checked-in generated C effectively becomes the open-source project's canonical source.

AI-generated code will make this distinction much messier.

If a model produces code from a conversation that cannot later be reproduced exactly, then:

> **Is the generated program actually the source, while the prompt is merely provenance?**

That is a surprisingly deep version-control question.
