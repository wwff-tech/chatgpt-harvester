# 3. Machine-Native Runbooks


## Problem Statement

Most runbooks are written for humans.

Observability vendors increasingly argue that future telemetry consumers are agents rather than operators. 

Runbooks rarely contain:

- structured decision logic,
- confidence thresholds,
- delegation boundaries,
- machine-readable context.

## Approaches

### Approach A

Create machine-readable runbooks.

Include:

- actions,
- preconditions,
- rollback paths,
- escalation policies.

### Approach B

Build hybrid runbooks:

- machine-executable,
- human-reviewable,
- continuously validated.

## Suggested Tech Hints

- YAML schemas
- Decision trees
- Policy engines
- OpenTelemetry
- Event-driven automation

## Suggested Formats

- Open-source framework
- Incident platform extension
- Internal developer platform module

## Why It Is A Good Fit

- Strong SRE relevance
- Clear migration path
- Agent-native future

## Why It Is Not A Good Fit

- Requires behavioural standardisation
- Hard to maintain over time
